# 需求说明书 · exhentai-manga-manager「类别」显示与筛选缺陷修复

> 版本 v1.1 · 需求分析师 许清楚 · 契约冻结版（开发期间不得偏离第 4 章口径）
> v1.1 变更（依据架构评审：技术选型冻结为「方案 A」，见第 12 章）：R2b/R3/R9/R10/R11/R12 修订，F-003/F-005 改口径，AC12 措辞修正，AC15 拆为 AC15-a/b/c，新增 RK6。
> 编号口径（以 v1.1 落盘为准，测试用例按此编号）：**AC15-a = 已消失类别键；AC15-b = `doujinshi`/`AI图集` 未选中且生效；AC15-c = 取消 `Doujinshi` → 97 本消失**。

## 1. 项目概述

- **一句话定位**：修复「管理 → 更改类别」下拉、本地筛选类别按钮、筛选重置按钮三处，使它们统一以 `book.category` 的**原始值**为唯一事实来源。
- **目标用户**：本地库有自建/自定义类别（如「AI图集」「单行本」「同人志」「小说」）的单机用户。
- **核心价值**：让"看到的类别" = "库里的类别" = "改出来的类别"，消除"选了同人志却写成 Doujinshi"的静默改数据行为。
- **成功标准（可量化）**：
  1. 本地库内两处界面（更改类别下拉 / 筛选类别按钮）的类别集合，与「设置 → 标签 → 类别标签 → 类别」行显示的集合**完全相等**（当前实测库为 8 项：AI图集、Artist CG、Doujinshi、Manga、Misc、单行本、同人志、小说）。
  2. 两处界面显示文本**无重复**（重复项数量 = 0）。
  3. 点「重置」后，未恢复选中的类别按钮数量 = 0。
  4. 任一类别按钮"只看这一类"的结果集，与按 `book.category` 原值 `WHERE` 出的数量一致（当前库 20/97/7/10/1/1/10/3 可逐一对账）。

## 2. 用户角色与权限

| 角色 | 说明 | 可做的事 | 不能做的事 |
|---|---|---|---|
| 本地库管理者（唯一受影响角色） | 拥有本地 `metadata.sqlite` 库的个人用户，库中类别中英混存 | 在「管理」视图批量改类别；在筛选弹窗按类别筛选/只看一类/重置；在设置里查看类别清单 | 不能在本期功能内重命名/合并/删除库里已有的类别值 |
| EH 在线用户 | 使用 exhentai 在线搜索的用户 | 使用筛选弹窗（类别 = EH 站点 10 类） | 其筛选命名空间不受本次改动影响，也不得被本地类别污染 |
| 系统（非人类角色） | 列表就地过滤 `ehFilterMatch` | 按 `book.category` 原值（大小写不敏感、空值按 Misc）判定 | 本期不改其匹配算法 |

## 3. 核心业务流程

### 流程 1：批量更改类别（管理视图）
1. 本地库管理者 在「管理」视图勾选 N 本书 → 右侧「更改类别」下拉展开 → 看到**库中实际存在的类别原值清单**。
2. 管理者 选中一项（如「单行本」）→ 点「应用」→ 系统把 N 本书的 `book.category` 写成该**原值**「单行本」→ 提示应用成功。
3. 管理者 回到设置 → 标签 → 类别标签 → 「单行本」计数增加，且**不新增**任何英文/中文变体条目。

### 流程 2：按类别筛选（本地库）
1. 管理者 点漏斗开筛选 → 类别按钮 = 库中实际类别（每个原值恰好 1 个按钮，两两不同名）。
2. 管理者 单击某按钮 → 该按钮变未选中；再次单击 → 恢复选中。
3. 管理者 长按/右键某按钮 → 只看这一类（其余全不选中）。
4. 点「确定」→ 列表立即按条件过滤；取消选中的类别对应的书从列表消失。
5. 漏斗按钮高亮表示"筛选正在生效"。

### 流程 3：重置筛选
1. 管理者 打开筛选，改过类别/语言/页数/评分 → 点「重置」。
2. 系统一次性恢复默认：**所有**类别按钮（含库内动态类别）全部选中、语言"不限"、页数"不限"、评分 0 星、关键词清空、黑名单内容保留但开关回到默认关闭。
3. 点「确定」→ 列表恢复为未筛选时的全量（书数相等），漏斗不再高亮。

## 4. 业务规则与口径（契约，冻结）

| 编号 | 规则 | 说明 |
|---|---|---|
| R1 | **唯一事实来源（SSOT）** = `book.category` 的去空白原值集合，取数经 `appStore.tagListRaw` 中 `cat === 'category'` 的 `tag` 值；与「设置 → 标签 → 类别标签」的「类别」行同源同集 | 禁止任何界面再用 `pinia.js` 的静态 `categoryOption` 或 `EH_FILTER_CATEGORIES` 作为**本地库**类别来源 |
| R2 | **显示文本 = 原值**，不做中英映射/词库翻译 | 「Doujinshi」显示 `Doujinshi`，「同人志」显示 `同人志`。把 `Doujinshi` 显示成「同人志」正是 D-02 的成因，必须去掉 |
| R2b | **key 与 label 分离**：显示 label 恒为原值；内部 key 允许是 EH key（原值恰好等于某 EH 英文名时，如 `Doujinshi → doujinshi`）或原值本身（自建类别，如 `AI图集`）。key 不外显、不参与"是否重复"的判定 | 用户看到的按钮/选项集合必须与 R1 集合逐项相等。给筛选 model 用 EH key 是 `ehFilter.js` 既有硬约束，**不是**可自由选择的实现细节（见 RK6） |
| R3 | **写入值 = 原值**（`book.category` 场景），不做大小写/语言归一、不二次推断；注意此处的"值"是原值，不是 R2b 的内部 key | 点「单行本」就写 `单行本`；点 `Doujinshi` 写 `Doujinshi`，绝不写 `doujinshi` |
| R4 | **去重口径**：按 `String(v).trim()` 后 `toLowerCase()` 去重；去重后保留排序中首次出现的原始写法作为 key 与显示文本 | 应对 `Doujinshi` / `doujinshi` 并存 |
| R5 | **空值剔除**：`category` 为空串或全空白的书**不产生**类别项，也不产生空文本按钮 | 当前库有 3 本 `category=''`，设置页也只显示 8 项 |
| R6 | **排序**：本地库按原值升序（保持 `tagListRaw` 现有排序结果，ASCII 在前、中文在后）；在线模式按 `EH_FILTER_CATEGORIES` 固定顺序 | 保证可复现、可与截图逐项对照 |
| R7 | **空集合回退**：本地库无任何类别值（或全库标签尚未加载）→ 两处均回退为 `EH_FILTER_CATEGORIES` 的 10 项，顺序固定 | 不允许出现空白下拉/空白按钮区 |
| R8 | **模式隔离**：`online === true` 时类别与语言一律用 EH 常量，且不得出现库内动态类别；EH 的 `f_cats` 位掩码只由 EH 10 键计算 | 在线筛选语义零改动 |
| R9 | **只清理「已消失的动态类别键」，EH 10 键一律保留**：① **全新启动**路径由既有构造自然丢弃（`syncFromProps` 只遍历 `Object.keys(model)`、`apply` 只提交 `{...model}`），无需新代码；② **同会话**路径（会话中途删改类别，某动态键失去对应类别，`:404` 兜底分支 `: model[k]` 保留旧值，`apply` 会把它写回快照）由**主理人裁决按已知边界处理（本期不实现清理）**，成因链路与未来加固方案存档于技术方案 §2.4b；③ EH 10 键**永不剔除**——`normalize` 会补回，且是已知类别的过滤键（`f_cats`/`ehFilterMatch` 依赖） | ②的唯一后果是**重置前**漏斗常亮（界面上已无该按钮，用户自查不出原因）；点「重置」即自愈（R10 会把非 base 键一律置 `true`），故**不产生 AC 影响**，AC1~AC16 全部不依赖该清理 |
| R10 | **重置 = 一次性恢复默认**：`resetAll` **遍历 model 的全部键**——base 内的键取 base 值，**其余键（动态类别、已消失类别的残留键）一律置 `true`**；`blacklist`（黑名单标签内容）**保留不动**；EH 10 键必须保留 | 判据（只判行为、不指定实现）：重置并确定后 `ehFilterActive(filter) === false`，等价于快照里所有类别键（含已消失类别的残留键）均为 `true`。⚠ 正向约束：**遍历范围不得收窄**为 `categories` 或 `Object.keys(defaultEhFilter())`——那样残留 `false` 会留下、`ehFilterActive` 恒为 `true` → AC9 挂，且这正是 D-03 原始 bug 的形态 |
| R11 | 不改数据、不做类别合并/迁移、**不改 `normalize` / `ehFilterMatch` / `ehFilterParams`**、不改黑名单逻辑、不加类别新建能力 | 见第 6 章 Out of Scope。任何"必须改 normalize 才能成立"的方案一律作废 |
| R12 | **EH 同名类别必须继续用 EH key 作为筛选 model 的键**：原值 `Doujinshi` 的按钮，其 model 键必须是 `doujinshi`。若改用原值当键，`ehFilter.js:93` 会把缺失的 `doujinshi` 补成 `true`，导致取消勾选后书照旧显示（点了不生效） | 这是 R11（不改 normalize）推出的强约束，不是风格偏好 |

## 7. 异常场景清单

| 功能ID | 异常场景 | 期望表现 |
|---|---|---|
| F-001 | 库中没有任何 `category`（全 NULL/空串） | 返回空数组，由调用方按 R7 回退 EH 10 项；不抛错、不返回 `undefined` |
| F-001 | 全库标签尚未加载完（`allTags` 空且 `bookList` 空） | 同为空数组 → 回退 EH 10 项（瞬时英文清单可接受，加载完成后自动变为原值清单） |
| F-001 | 同时存在 `Doujinshi` 与 `doujinshi` | 只出 1 项（保留首次出现写法）；筛选时两种写法的书都能被这一项筛出 |
| F-001 | 存在 `category='   '`（全空白） | 剔除，不产生空文本选项 |
| F-002 | 下拉打开时当前选中值已不在集合中（类别被别处改掉） | **回显该原值**（`el-select` 无匹配 option 时直接回显 model 值），不崩、不改写成别的类别。不做"回显为空"的额外处理——原值即真相，且不强加 watcher |
| F-002 | 未勾选任何书就点「应用」 | 按钮保持 disabled（现状） |
| F-003 | 用户单击取消某类别后又点「重置」 | 该类别恢复选中（F-004 覆盖） |
| F-003 | 类别按钮被长按/右键「只看这一类」 | 仅该类选中（其余含 EH 键全置 `false`）；确定后其余书隐藏 |
| F-003 | 取消勾选 `Doujinshi`（EH 同名类别） | 该书必须真的被筛掉（键必须仍是 `doujinshi`，见 R12/RK6） |

## 11. 术语表

| 术语 | 含义 |
|---|---|
| 类别 / `book.category` | 书的一个独立字段，值可为 EH 官方英文名（`Doujinshi`）或用户自建中文名（`同人志`、`单行本`、`AI图集`、`小说`） |

| SSOT（唯一事实来源） | 第 4 章 R1 指定的取数口径，全 app 只此一处 |
| 重置 | 第 4 章 R10 定义的一次性恢复默认动作 |
| 只看这一类 | 长按/右键类别按钮，仅保留该类选中 |
| 内部 key | 筛选 model 里的键名。EH 同名类别用 EH key（`doujinshi`），自建类别用原值（`AI图集`）。**不外显**，用户只看到 label（原值） |
| label | 按钮/选项上显示的文本，恒等于类别原值（R2） |
