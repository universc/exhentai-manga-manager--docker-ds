**一句话理由**：`ehFilterMatch` 已按「key 本身 **或** key 对应的 EH name」小写匹配（`ehFilter.js:219-225`），显示与匹配可以解耦——只要把显示文本换成原值就能消掉两个「同人志」，而 key 保持在 EH 命名空间里，`normalize`（`ehFilter.js:93`，无条件保留 EH 键的勾选状态）才不会把用户的取消勾选吃掉。

**影响面**：4 个文件；零数据迁移；旧 `localStorage` 快照天然兼容（不新增、不删除任何 EH 键）。

**预验证**：已用真实库数据（8 项类别原值 / 149 本已分类书）与真实 `ehFilter.js` 实跑，AC4/AC5/AC6/AC7/AC9/AC13 的数值全部对上（明细见 §5.0）。开发不再做选型实验。

### 0.2 本期不做项与已知边界（主理人最终裁决，不再变更）

**`pruneStaleCatKeys` 不引入。** 三条用户报告的缺陷在无该项时已全部修复，且它不是任何 AC 的达标条件。裁决权衡（按权重）：

1. 无 AC 支撑，且缺陷已修完 → 无需求依据。
2. 需求 v1.1 的 R9 已**书面接受**该边界；req-analyst 是需求口径的 owner，主理人不在无 AC 支撑时推翻它。
3. **风险不对称**：修剪在「类别集合暂时不完整」（切库 / 标签尚未加载完）时可能**静默丢掉用户已保存的 `false` 勾选**，用户极难自查；不修剪的最坏表现是**漏斗常亮**，而本轮正好把「重置」改成全覆盖，点一次即可恢复。
4. 开发已按冻结版开工，改契约会引入返工与任务卡/评审口径二次漂移。

**已知边界（写在这里，避免后人当 bug 修）**：同一会话内把某个类别的书全部改走后（不重启），该类别键会残留在筛选 model 里，并可能被写回快照；表现为**漏斗一直高亮，但打开筛选看不到任何未选中的按钮**。用户点一次「重置」即恢复（重置会把它置 true）。技术成因与后续加固方案见 §2.4b，**本期不实现、不进任何验收项**。

## 2. 冻结契约

### 2.1 新 Pinia getter：`localCategoryValues`

| 项 | 冻结内容 |
|---|---|
| 名称 | `localCategoryValues`（`src/pinia.js`，getters 内，放在 `tagListRaw` 之后） |
| 输入来源 | **只读 `this.tagListRaw`**（= 全局 `allTags`，未加载时自动回退当前书架聚合）。**禁止**写 `state.tagListRaw`（`state` 上没有 getter，会抛），**禁止**在组件里再过滤一次 `cat === 'category'` |
| 返回 | `string[]`：去空白后的**原值**，按 `tagListRaw` 既有顺序（即原值升序，ASCII 在前中文在后），大小写不敏感去重（保留排序中首次出现的写法） |
| 空集 | 返回 `[]`（**不返回 undefined、不抛错、不做回退**；回退由调用方按 R7 处理） |
| 去重 | `v.trim().toLowerCase()` 为去重键（R4）；`trim()` 后为空则丢弃（R5） |
| 不做什么 | 不翻译、不做大小写归一写入、不读 `bookList`、不读 `setting`、**不返回 key**（key 的映射只允许在 §2.2 那一处做） |

```js
    // 「本地库的类别原值清单」—— 全 app 唯一的类别取数口径（需求 R1/R4/R5/R6）。
    // 取 tagListRaw 里 cat='category' 的原值:tagListRaw 已按「cat##tag 小写」去重并排好序,
    // 这里只补 trim + 空值剔除 + 大小写去重的兜底,保证空集/全空白/大小写并存都不会漏网。
    // ★ 用 this.tagListRaw 而不是 state.tagListRaw:state 里没有 getter,那样写会直接抛。
    // ★ 不再翻译:把 Doujinshi 显示成「同人志」正是「两个同人志」按钮的成因(R2)。
    localCategoryValues () {
      const out = []
      const seen = new Set()
      for (const item of this.tagListRaw) {
        if (!item || String(item.cat || '').toLowerCase() !== 'category') continue
        const value = String(item.tag || '').trim()
        if (!value) continue                                  // R5:空值不产生类别项
        const dedupeKey = value.toLowerCase()                 // R4:大小写去重,保留首次出现的写法
        if (seen.has(dedupeKey)) continue
        seen.add(dedupeKey)
        out.push(value)
      }
      return out
    },
```

> 为什么不放 utils.js：需求 F-001 冻结在 `pinia.js`；放 getter 才拿得到缓存与响应式。

### 2.2 本地筛选类别项结构（仅 `EhFilterDialog` 需要 key；对应需求 R2b/R12）

冻结结构 `{ key, name, bit, label }`：

| 原值类别 | key | name | bit | label | 说明 |
|---|---|---|---|---|---|
| EH 英文原名（`Doujinshi` / `Manga` / `Artist CG` / `Game CG` / `Non-H` / `Image Set` / `Western` / `Cosplay` / `Asian Porn` / `Misc`，大小写不敏感） | **对应 EH key**（`doujinshi` / `manga` / `artistCG` / …） | 原值 | 对应 EH bit | **原值** | R12：EH 同名类别必须继续用 EH key（过滤与 `normalize` 都依赖），label 是原值，所以 `Doujinshi` 显示 `Doujinshi` |
| 其他任意值（`AI图集` / `单行本` / `同人志` / `小说` …） | 原值本身 | 原值 | `0` | **原值** | 即现有「动态类别」 |

- **模板写法（冻结）**：`{{ c.label || galleryCategoryName(c.name, $t) }}`
  - 本地映射项带 `label`（= 原值）→ 显示原值，D-02 消失。
  - **在线分支与空集回退项不带 `label`** → 自动走译名，显示与今天完全一致。
  - 因此在线分支可以**原样 `return EH_FILTER_CATEGORIES`**，满足 R8/RK3 的字面要求。
- **映射只此一处**（req v1.1 的实现要求）：`localCategoryValues` 的返回值 → key 的映射（即 `EH_FILTER_CATEGORIES.find(...)` / `byName`）只允许出现在 `EhFilterDialog.categories` 内，且必须挂在 getter 结果上。任何第二份 EH 名比对都是 RK1 复发，评审打回。
- key 冲突兜底：映射后按 `key.toLowerCase()` 再去重一次（例如库里同时有 `Non-H` 与 `nonH`，两者都映射到 `nonH`），后者跳过——`v-for` 的 `:key` 不能重复。
- **写入库的值永远是 `name`/原值，不是 `key`**（R3）：`Doujinshi` 写 `Doujinshi`，绝不写 `doujinshi`。筛选 model 的键可以是 EH key，但 `book.category` 不行。

### 2.4 重置精确语义（`EhFilterDialog.resetAll`）

顺序固定：

1. `const base = defaultEhFilter(dynamicCatKeys.value)` —— 主理人冻结写法：当前动态类别键一并并入 base（D-03 本体修复）
2. `ensureDynamicCats()` —— 把当前类别集合补进 model
3. 遍历 `Object.keys(model)`：
   - `k === 'blacklist'` → **跳过**（R10：黑名单文本保留）
   - `base` 自身有该键（9 个保留字段 + EH 10 键 + 当前动态类别键）→ `model[k] = base[k]`
   - 其余键（会话中途消失的旧类别残留键）→ `model[k] = true`
4. `ratingStars.value = 0`
5. `newBlacklistTerm.value = ''`

判据：重置后 8 个按钮全为选中态（AC8）且 `ehFilterActive({...model})` 为 `false`（AC9）。
副作用（即 §0.2 的已知边界）：若 model 里有已消失类别的残留键，第 3 步会把它置 `true` —— 高亮随之消失，但键仍留在快照里（无害：没有书能命中它，且 `ehFilterActive` 也不会再为它亮）。

> **禁止**把第 3 步的「其余 → `true`」改成「其余 → `delete`」：删掉会让 `model['同人志']` 变 `undefined`，模板 `:class="{'is-on': model[c.key]}"` 判为未选中 → **AC8 失败**。本期**不做**任何剔除（§2.4b 的方案本期不实现）。
>
> **与 AC9 的耦合（必须看清）**：若 `model` 里残留了已消失类别的 `false`，`ehFilterActive`（`ehFilter.js:177-182`）会**一直返回 true** → AC9 会挂。本版**不依赖 prune 也能过 AC9**，原因是第 3 步遍历的是 `Object.keys(model)`（含残留键）→ 残留键被置 `true` → 再无 false 的动态键 → `ehFilterActive` 返回 false。**因此严禁把遍历范围收窄成 `categories` 或 `defaultEhFilter()` 的键**：那样残留 `false` 会留下来，AC9 必然失败（那正是 D-03 原始 bug 的形态）。

```js
const resetAll = () => {
  // 主理人冻结写法:base 带上当前动态类别键,这样第 3 步「base 有该键」分支就能把动态类别一并置 true
  const base = defaultEhFilter(dynamicCatKeys.value)
  // 遍历 model 的**全部**键 —— 动态类别(AI图集/单行本/…)也会被重置,
  // 而不是像以前那样只遍历 defaultEhFilter() 的键,把动态类别原封不动留着(R10)。
  ensureDynamicCats()
  for (const k of Object.keys(model)) {
    if (k === 'blacklist') continue                       // 黑名单内容保留,只把开关回默认
    model[k] = Object.prototype.hasOwnProperty.call(base, k) ? base[k] : true
  }
  ratingStars.value = 0
  newBlacklistTerm.value = ''
}
```

### 2.4b 已知边界与**后续可选加固**（本期不实现，仅存档）

> ⚠ 本节是**文档记录**，不是本期任务。**不要实现、不要写进验收项。**

**边界现象**：同一会话内把某个类别的书全部改走后（不重启），该类别键会残留在筛选 `model` 里并可能被 `apply` 写回快照。表现为**漏斗一直高亮，但打开筛选看不到任何未选中的按钮**（该类别按钮已不存在）。用户点一次「重置」即恢复。

**成因链路**（已核到行，供后续排查）：

1. `model` 是 `reactive`、setup 期建一次、跨多次打开复用；`ensureDynamicCats`（`EhFilterDialog.vue:326-330`）只加不删。
2. 会话中期类别消失后，`model` 里的旧键仍在。
3. 下次打开时 `syncFromProps`（`:400-405`）按 `Object.keys(model)` 遍历，该键 `in src` 为假、也不在 `dynamicCatKeys` 里 → 命中 `:404` 的兜底分支，**保留旧值**（此前被取消过就是 `false`）。
4. `apply`（`:447`）提交 `{...model}` → `normalize` 保留布尔动态键 → 写回快照。
5. `ehFilterActive`（`ehFilter.js:177-182`）见到任意 `false` 的动态键即 `return true` → 漏斗常亮。

**若后续要修**（未来的完整实现，8 行，需同时满足下列三条，否则不如不修）：

```js
const pruneStaleCatKeys = () => {
  // ① 集合为空时(标签未加载完/真空库)不修剪,否则会把用户已保存的 false 勾选全抹掉
  if (!props.online && !(appStore.localCategoryValues || []).length) return
  // ② keep 基线复用 defaultEhFilter() 的 19 个键,不要另抄 RESERVED 名单(会漂移);EH 10 键永不删
  const keep = new Set(Object.keys(defaultEhFilter()))
  for (const c of categories.value) keep.add(c.key)
  for (const k of Object.keys(model)) if (!keep.has(k)) delete model[k]
}
```
- ③ 挂载点与时机：`syncFromProps` 末尾 + `resetAll` 中**置 true 之前**；函数**必须**定义在 `model`/`ensureDynamicCats`（`:330`）之后、`syncFromProps()` 首次执行（`:407`）之前，否则 setup 期 TDZ ReferenceError。
- 另需评估「类别集合暂时不完整（切库 / 标签未加载完）」时的误删风险 —— 这正是本期决定不做的主因（§0.2 第 3 条）。

```js
// 类别按钮:在线分支**原样返回** EH 常量(R8/RK3 的字面要求,一行不改);
// 本地库 = 库中实际存在的类别原值(R1/R2/R6):EH 英文原名仍映射到 EH key,只把 label 换成原值。
// ★ 为什么 key 仍然留在 EH 命名空间(R12):model 的键必须和 ehFilterMatch 的口径一致
//   (它按「key 小写」或「该 key 的 EH name 小写」双路匹配),而 normalize 会无条件保留 EH 键的
//   false —— 于是「取消勾选 Doujinshi」才能真正筛掉那 97 本(AC15-c)。
const categories = computed(() => {
  if (props.online) return EH_FILTER_CATEGORIES          // 在线命名空间,零改动
  const used = appStore.localCategoryValues || []
  if (!used.length) return EH_FILTER_CATEGORIES          // 空集合回退(R7),显示走模板译名 = 与今天一致
  const byName = new Map(EH_FILTER_CATEGORIES.map(c => [c.name.toLowerCase(), c]))
  const seen = new Set()
  const out = []
  for (const name of used) {
    const hit = byName.get(String(name).toLowerCase())
    const key = hit ? hit.key : name
    // 同一 EH key 只能有一个按钮(如库里同时存在 Non-H 与 nonH),否则两个按钮抢同一个 model 键
    if (seen.has(key.toLowerCase())) continue
    seen.add(key.toLowerCase())
    out.push({ key, name, bit: hit ? hit.bit : 0, label: name })
  }
  return out
})
```

**删除项**：第 289 行 `const used = valuesOfTagCat('category')` 与旧的 `byName`/`out.push(hit || …)` 写法（已含在整体替换里）。`valuesOfTagCat` 函数本体保留，仅供 `languages` 使用。
