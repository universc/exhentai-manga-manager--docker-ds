## 5. 复现构建(需要重新出包时)

```bash
# 前端 + Windows 安装包(nsis + zip)
npm run build
npx electron-builder --win nsis zip
```

产物落在 `out/`。本轮实测:前端约 13s,electron-builder 约 100s。

```bash
# Docker(必须在 NAS 上跑;本机无 docker)
# 先把源码同步到 /vol1/1000/docker/exhentai-manga-manager,然后:
cd /vol1/1000/docker/exhentai-manga-manager
sudo docker build -t exhentai-manga-manager:1.16.0 \\
  -t universc/exhentai-manga-manager--docker-ds:1.16.0 \\
  -t universc/exhentai-manga-manager--docker-ds:latest .
```

**踩过的坑(务必照做)**:
1. **不要用 `docker compose`**(用户明确要求)。用 `docker build` + `docker run`。
2. 构建若出现大量 `CACHED`,说明源码层没更新——先确认 `src/` 已同步,必要时 `--no-cache`。
3. **只同步部分文件会构建失败**:例如 `Setting.vue` 引用了 `utils.js` 的 `tagColorOf`,若 `utils.js` 是旧的,
   `vite build` 会报 `"tagColorOf" is not exported`。判断办法:把所有 `src/**` 与 NAS 逐一 md5 比对,只传差异,
   但**差异要传全**,不要手工挑。
4. 重建容器时必须**先 `docker rm -f`** 再 `docker run`,否则 `--name` 冲突。

容器启动参数(照抄,含 4 个挂载与核显):

```bash
sudo docker run -d --name exhentai-manga-manager --restart unless-stopped -p 10000:10000 \\
  -e WEB_DATA_DIR=/data -e LIBRARY_DIR=/library -e WEB_LIBRARY=/library -e WEB_PORT=10000 \\
  -e WEB_ADMIN_USER=universc -e WEB_ADMIN_PASSWORD=<见第 6 节> -e TZ=Asia/Shanghai \\
  --device /dev/dri:/dev/dri \\
  -v /vol3/1000/01/01-漫画/S/数据存放:/data \\
  -v /vol3/1000/01/01-漫画:/library \\
  -v /vol3/1000/01/03-小说:/xiaoshuo \\
  -v /vol4/1000/下载:/download \\
  universc/exhentai-manga-manager--docker-ds:1.16.0
```
> `/download` 这一条 `docker-compose.yml` 里**没有**,但线上容器有。不要漏。

## 8. 已知的"看着像 bug 其实不是"

- **H@H 归档列表为空 / 提示登录**:归档页 `archiver.php` 未登录会 302 到登录页。必须登录 EH 才能用,
  且链接写在 `onclick="return popUp(...)"` 里(`href` 是 `#`)。测试环境没 Cookie 时只会看到登录提示,这是**正确行为**。
- **EH 图片偶发 `ECONNRESET`**:EH 的 H@H 节点本身有波动。换节点重试能把失败率压很低但**不是 100%**。
  若用户仍频繁失败,把「请求频率限制」调成 1 个/秒更稳。
- **搜索/排序/重新加载时出现的骨架屏**:这是刻意行为(先清空再渐进加载),另有 8 秒兜底会自动收起。
